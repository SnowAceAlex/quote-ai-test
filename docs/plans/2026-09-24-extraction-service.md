# Document Extraction Service – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (recommended)
> or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`)
> syntax for tracking. Each phase is one branch; each task is one commit.

**Goal:** A PDF-in / JSON-out service that extracts supplier line items with page-and-source-text
evidence and refuses anything it cannot point to, plus an upload page that shows refusals in plain
language.

**Architecture:** One Next.js 16 app deployed to Vercel. Part A is a framework-free engine in
`src/lib/extraction/` (pdf.js text items → rows → table → rules) behind a `POST /api/extract` route
handler. Part B is a client page that talks to that route through a small client that never collapses
a failure into a generic message.

**Tech stack:** Next.js 16.3 (App Router, Turbopack), React 19, TypeScript 5.9, Tailwind 4,
`unpdf` 1.8 (serverless build of pdf.js), `zod` 4, Vitest 5, pnpm 11, Vercel.

## Global constraints

- Every extracted value carries `{ page, sourceText }`, and its `raw` string appears verbatim in
  `sourceText`. No exceptions, including header fields and totals.
- No derived number is ever presented as an extracted value. Derived numbers appear only inside a
  refusal's `calculation`, next to the stated inputs.
- A refusal is HTTP 200. HTTP 4xx/5xx is only for "could not process the request at all".
- A failure on one page or row never removes data from other pages or rows.
- Money is handled in integer cents internally. Output keeps the stated `raw` string.
- Currency is reported as the symbol the document uses (`$`). We never claim NZD or AUD.
- GST rate comes from the document's own label (`GST (15%)`), never a hard-coded constant.
- Upload limit 4 MB (Vercel caps function request bodies at 4.5 MB).
- Comments: only a non-obvious why, one short human line. No docstring essays.
- Commits: conventional with scope, no Claude co-author trailer.

## 2. Response contract

Lives in `src/lib/extraction/schema.ts`; the API validates its own output against it and the UI
validates what it receives.

```ts
import { z } from "zod";

export const Evidence = z.object({
  page: z.number().int().min(1),
  sourceText: z.string().min(1), // the whole text line, runs joined by single spaces
});

export const SourcedNumber = z.object({
  value: z.number(),
  raw: z.string().min(1),
  evidence: Evidence,
});

export const SourcedMoney = SourcedNumber.extend({
  per: z.string().nullable(), // "carton" for "$74.00 /carton"
});

export const SourcedText = z.object({
  label: z.string(),
  raw: z.string().min(1),
  evidence: Evidence,
});

export const LineItem = z.object({
  id: z.string(), // "p1-l3"
  page: z.number().int().min(1),
  evidence: Evidence,
  code: z.string().nullable(),
  description: z.string(),
  quantity: SourcedNumber.nullable(),
  unit: z.string().nullable(),
  unitPrice: SourcedMoney.nullable(),
  amount: SourcedMoney.nullable(),
  otherColumns: z.array(SourcedText), // columns we show but don't interpret, e.g. Weight
  warningIds: z.array(z.string()),
});

export const FindingCode = z.enum([
  "NO_TEXT_LAYER",     // page is an image
  "PAGE_UNREADABLE",   // parser failed on this page
  "NO_TABLE_FOUND",    // text but no recognisable line-item table
  "ROW_UNPARSEABLE",   // row doesn't fit the table's columns
  "VALUE_UNPARSEABLE", // a cell in a number format we won't guess at
  "NOT_STATED",        // the document never gives this value
  "AMBIGUOUS",         // stated, but its meaning is unclear
  "CONTRADICTION",     // two statements disagree
  "DOES_NOT_ADD_UP",   // arithmetic between stated values fails
  "NOT_AN_INVOICE_PAGE",
  "MISSING_SECTION",
]);

export const Finding = z.object({
  id: z.string(),
  code: FindingCode,
  scope: z.enum(["document", "page", "line", "field"]),
  page: z.number().int().nullable(),
  lineItemId: z.string().nullable(),
  subject: z.string(),              // "Total (incl GST)", "Number of cartons", "Page 4"
  reason: z.string(),               // plain English, with the specific values
  evidence: z.array(Evidence),      // empty for NO_TEXT_LAYER, 2+ for CONTRADICTION
  calculation: z.string().nullable(), // "$1,270.00 + $190.50 = $1,460.50"
});

export const Totals = z.object({
  subtotal: SourcedMoney.nullable(),
  gst: SourcedMoney.extend({ ratePercent: z.number().nullable() }).nullable(),
  total: SourcedMoney.extend({ includesGst: z.boolean().nullable() }).nullable(),
});

export const PageSummary = z.object({
  page: z.number().int().min(1),
  status: z.enum(["read", "refused"]),
  title: z.string().nullable(),
  lineItemCount: z.number().int(),
});

export const ExtractionResult = z.object({
  fileName: z.string(),
  pageCount: z.number().int(),
  outcome: z.enum(["complete", "partial", "nothing_extracted"]),
  pages: z.array(PageSummary),
  fields: z.array(SourcedText), // Document No, Date, Bill to, Job ref...
  lineItems: z.array(LineItem),
  totals: Totals,
  refusals: z.array(Finding), // things we did not extract
  warnings: z.array(Finding), // things we extracted but a person should check
});

export const ErrorCode = z.enum([
  "NO_FILE", "EMPTY_FILE", "NOT_A_PDF", "FILE_TOO_LARGE",
  "PDF_ENCRYPTED", "PDF_CORRUPT", "INTERNAL",
]);

export const ErrorBody = z.object({
  error: z.object({ code: ErrorCode, message: z.string() }),
});

export type ExtractionResult = z.infer<typeof ExtractionResult>;
// ...one `export type X = z.infer<typeof X>` per schema above
```

`outcome`: `nothing_extracted` when there are no line items; otherwise `partial` if any refusal
exists, else `complete`. Warnings alone don't downgrade `complete`.

A value that fails a check is **moved out of** `totals`/`lineItems` and into `refusals` with its
source line in `evidence`. Anything left in the extracted lists is safe to use.

### Task 1.4: Table detection and line items

**Files:** create `table.ts`, `table.test.ts`

**Produces:**
```ts
type Column = { label: string; x: number; role: "code" | "description" | "qty" | "unit" | "unitPrice" | "amount" | "other" };
type TableParse = { header: Row; columns: Column[]; lineItems: LineItem[]; rowFindings: Finding[]; endIndex: number };
parseTable(rows: Row[], page: number): TableParse | null; // null → NO_TABLE_FOUND
```

Rules:
- Header = first row whose cells include `Description` and `Qty` (case-insensitive).
- Roles from header labels: Code, Description, Qty/Quantity, Unit, Unit Price/Price, Amount/Total/Line Total.
  Anything else (Weight) → `other`, carried in `otherColumns` as raw text only.
- A cell belongs to the column with the greatest `x` ≤ `item.x + 2`.
- Skip the dashed rule row (`/^-+$/`).
- Table ends at the first row that either starts with a label ending in `:` (Subtotal:, Total:,
  Warehouse notes:) or sits more than 1.5× the header-to-first-row gap below the previous table row
  (samples: rows 17pt apart, footers 35–40pt below). Footers therefore never become table rows.
- Inside the table, a row missing description or qty → `ROW_UNPARSEABLE` finding quoting the row;
  other rows continue.
- Line item ids are `p<page>-l<n>` (n is 1-based per page). Finding ids are
  `<kind>:<suffix>` strings unique per document, e.g. `row:p1-l3:qty`.
- A money/qty cell that fails the strict parser → field set to `null` + `VALUE_UNPARSEABLE` finding.
- Every sourced field gets `evidence = { page, sourceText: row.text }`.

Tests:
- IB-55871 → 4 items; item 1 `quantity.value 24`, `unitPrice.value 52`, `amount.value 1248`,
  `amount.raw "$1,248.00"`.
- IB-56010 → 4 items, `amount` null, `unitPrice.per` = carton/ea/kit/tub,
  `otherColumns[0]` = `{ label: "Weight", raw: "640g total" }` for FX-402.
- Synthetic rows where one qty cell is `approx 20` → that item's `quantity` null + one
  `VALUE_UNPARSEABLE` finding, the other items intact.

- [ ] Commit `feat(extraction): parse line-item tables by header columns with row evidence`.

### Task 1.5: Header fields, title, totals block, orchestrator

**Files:** create `document.ts`, `extract.ts`, `extract.test.ts`

**Produces:**
```ts
readTitle(rows: Row[]): string | null;          // row directly under the company name
readFields(rows: Row[], page: number): SourcedText[]; // "Label: value" rows above the table
readTotals(rows: Row[], page: number): Totals;  // "<label>: <money>" rows below the table
freeTextRows(rows: Row[], table: TableParse | null): Row[]; // every row not title/header/table/totals
extractDocument(bytes: Uint8Array, fileName: string): Promise<ExtractionResult>;

// src/lib/extraction/rules/types.ts – phase 2 rules plug in here
type PageRead = { page: number; status: "read" | "refused"; title: string | null; rows: Row[]; table: TableParse | null; freeText: Row[] };
type RuleContext = { pages: PageRead[]; lineItems: LineItem[]; totals: Totals; fields: SourcedText[] };
type RuleResult = {
  refusals: Finding[];
  warnings: Finding[];
  refuseTotals?: Array<"subtotal" | "gst" | "total">; // set to null in the output
  refuseAmounts?: string[];                            // line item ids whose amount becomes null
  lineWarnings?: Array<{ lineItemId: string; warningId: string }>;
};
type Rule = (ctx: RuleContext) => RuleResult;
// src/lib/extraction/rules/index.ts
export const rules: Rule[] = []; // phase 2 appends here
```

Field rows: a row matching `Label: value` above the table where the label is at most 3 words and
the value does not end with `.` – so "Document No: IB-56010" is a field, while "Summary: 9 cartons
dispatched from Ironbark warehouse this run." stays free text for the contradiction rule.

Totals rows: `row.text` matches `^(.+?):\s*(\S+)$` below the table and the value parses as money.
Label containing `GST` → `gst` (rate via `parsePercent`); label starting `Subtotal` → `subtotal`;
label starting `Total` → `total`, `includesGst` true if the label says `incl GST`, false if
`excl GST`, else null.

`extractDocument` loops pages with a `try/catch` per page: no items → `NO_TEXT_LAYER` refusal
(scope page), thrown error → `PAGE_UNREADABLE` refusal, no table → `NO_TABLE_FOUND`. Then runs
every rule in `rules`, applies their removals, attaches line warnings, and computes `outcome`.
Validates its own output with `ExtractionResult.parse` before returning.

Tests:
- IB-55871 → outcome `complete`, fields include `Document No` = `IB-55871`, totals
  subtotal 3259 / gst 488.85 rate 15 / total 3747.85 `includesGst: true`.
- IB-55902 → outcome `nothing_extracted`, one refusal `NO_TEXT_LAYER` page 1.
- IB-STMT47 → 21 items, refusal `NO_TEXT_LAYER` on page 4 only, pages 1–3 and 5–8 `read`.

- [ ] Commit `feat(extraction): orchestrate per-page extraction with page-level containment`.
- [ ] Push, open PR `Phase 1: extraction core`, merge.

## Phase 2 – Refusal rules · branch `feat/phase-2-refusal-rules` (~1.5 h)

Each rule is a `Rule` from `src/lib/extraction/rules/types.ts` (defined in Task 1.5): a pure
function of `RuleContext` returning a `RuleResult`. Register it in `rules/index.ts`; `extract.ts`
already applies `refuseTotals`, `refuseAmounts` and `lineWarnings`. Rule tests build a
`RuleContext` directly (or run `extractDocument` on a sample) – no PDF mocking.

### Task 2.1: Arithmetic checks

**Files:** `rules/arithmetic.ts`, `rules/arithmetic.test.ts`

- Line: `qty × unitPrice` vs `amount` (cents, exact). Mismatch → `DOES_NOT_ADD_UP` refusal on
  the line's `amount`, calculation shown, `amount` removed. Skip when `per` differs from `unit`.
- Lines → subtotal: sum of amounts vs stated subtotal. Only if every page was read and every line
  has an amount; otherwise no check (and no claim that it checked).
- GST: `subtotal × rate` rounded to cents vs stated GST.
- Total: `subtotal + GST` vs stated total when `includesGst`; else lines vs total.
- On any mismatch the **stated figure that breaks the chain** is refused. If it's ambiguous which
  one (e.g. subtotal and total both disagree with lines), refuse every figure involved.

Tests: IB-56150 → one `DOES_NOT_ADD_UP` refusal, subject `Total (incl GST)`, calculation
`$1,270.00 + $190.50 = $1,460.50`, 3 evidence lines, `totals.total` null, subtotal and GST kept.
IB-55871 → no findings. Synthetic line `10 × $46.50 = $456.00` → line amount refused.

- [ ] Commit `feat(rules): refuse stated totals that don't add up, showing the calculation`.

**Files:** `src/app/api/extract/route.ts`, `src/app/api/extract/route.test.ts`

- Success → 200 `ExtractionResult`, `Cache-Control: no-store`.
- If `next build` complains about pdf.js bundling, add `serverExternalPackages: ["unpdf"]` to
  `next.config.ts` and note why in one line.

Tests call the exported `POST` with a `Request` built from `FormData`: each error code, IB-55871
→ 200 complete, IB-55902 → 200 `nothing_extracted` (a refusal is not an error).

**Files:** `src/lib/client/extract-client.ts`, `extract-client.test.ts`

## Decisions

| # | Decision | Why |
|---|---|---|
| D1 | Deterministic layout parser, no LLM in v1 | Evidence has to be verbatim and testable; an LLM can paraphrase or invent. Unknown layouts fail closed (`NO_TABLE_FOUND`). |
| D2 | Scanned pages are refused, not OCR'd | OCR text can't be checked against a text layer; adds weight and latency on Vercel. |
| D3 | Refusal = 200, error = 4xx/5xx with code + message | A correct refusal must never look like a failure to the client. |
| D4 | Derived numbers only inside `calculation` | Keeps the "every number has a source" rule literal. |
| D5 | Refused values leave the extracted lists | Anything in `lineItems`/`totals` is safe to use without reading the refusals. |
| D6 | One Next.js app, engine framework-free | Single Vercel deploy; `src/lib/extraction` can move to its own service unchanged. Plain route handler instead of tRPC because the service must accept file uploads and be callable with curl. |
| D7 | Samples live in `public/samples` | Same files feed the tests and the "Try a sample" buttons. They're non-customer documents. |
| D8 | 4 MB upload cap | Vercel rejects bodies over 4.5 MB before our code runs. |
